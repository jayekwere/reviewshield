# Isolated static scan worker

The default web image is an offline SARIF evaluator. `Dockerfile.scanner` is a separate credential-free Semgrep worker. It scans Python files with the repository's trusted local rule pack and never executes target source. The bundled rule detects direct `eval(input(...))` syntax; it does not follow indirect parameter flows. It makes no claim to assess other languages or every vulnerability class. CodeQL remains a separate SARIF producer.

```sh
mkdir -p artifacts
docker build -f Dockerfile.scanner -t reviewshield-scanner .
docker run --rm --network none --read-only --cap-drop ALL \
  --security-opt no-new-privileges --user 10001:10001 \
  --pids-limit 128 --memory 1g --cpus 1 \
  --tmpfs /tmp:rw,noexec,nosuid,size=128m \
  --mount "type=bind,source=$PWD/fixtures,target=/input,readonly" \
  reviewshield-scanner > artifacts/worker-verification.json
node --import tsx scripts/verify-worker.ts artifacts/worker-verification.json
```

The runtime flags in this command enforce network and resource restrictions; the image alone does not impose all of them. Mount only the source selected for review. Never mount the App key, webhook secret, identity files, host credential directories or container socket. Keep the privileged publisher outside this worker.

The worker copies bounded Python files into a temporary clean input tree before scanning. PR-controlled ignore files and repository configuration are excluded from that tree, and symlinks are rejected. Limits are 10,000 traversed entries, 500 Python files, 1 MB per Python file, 8 MiB total source, a 120-second scanner deadline, and post-run 8 MiB acceptance checks on captured stdout and the SARIF file. Stdout and stderr are buffered before those checks; stderr has no separate byte cap. The supplied container memory limit bounds the worker process environment as a separate control. An empty declared Python scope is an error. Operator-selected rules and the worker image are trusted configuration.

Native Semgrep JSON must report every declared Python file as scanned and contain no parser or scanner errors. Exit failure, skipped files, missing coverage and malformed report locations cannot become a clean report. The worker emits native SARIF, source SHA-256 values and explicit expected/scanned coverage. A trusted coordinator must bind those exact bytes and changed lines to the queued PR's current head/base before publication. `runJob` independently rechecks the live PR revision and numeric base-repository ID.

For a live App, build the scanner image with the default `reviewshield-scanner` tag, start `node dist/src/app.js webhook`, then run `node dist/src/app.js worker` in a separate process with the same private `BINDINGS_FILE` and `QUEUE_PATH` plus `APP_ID` and `APP_KEY_FILE`. `WEBHOOK_SECRET` is needed only by the receiver. Keep these files private and outside source control. `SCANNER_IMAGE` selects an operator-trusted scanner image. The coordinator fetches exact native GitHub blobs, verifies their Git hashes and byte counts, and sends a strict bounded source manifest over container standard input. It does not mount host source or credentials. The worker validates paths, sizes and SHA-256 values before creating private source files. No Docker socket enters the scanner container. Use `node dist/src/app.js work JOB_SHA256` for a single queued event. Completed or claimed jobs cannot be claimed again; a crashed processing job requires investigation before deliberate recovery. Legacy queued receipts lacking installation/repository numeric IDs are rejected. Do not execute PR build scripts, dependency installers, hooks or imported Python code in the publisher process. The changed-file coordinator supports at most 299 changed files, 1 MB per Python file and 8 MiB total source. It uses an immutable comparison and SHA-pinned directory membership, with a 1,000-read budget and nontruncated 4 MiB API responses. The standalone scanner manifest retains its 500-Python-file limit. Missing or truncated patches, malformed UTF-8, missing blob evidence and changed live PR identities fail without a clean check. Other languages and deleted files are explicitly unassessed; a PR with no Python scope cannot produce a clean result. This is a configured-rule review of changed Python files, with no whole-repository or complete vulnerability-coverage claim. There is no hosted production App deployment in this repository.

The verification workflow executes this exact restricted container against synthetic source and asserts the real Semgrep rule, source digest, path, line, severity, file coverage and blocking review decision. Its synthetic head/base values do not represent a live App test. Live App account acceptance is recorded separately when exercised. Package version and scanner-reported version are preserved independently as described in the main verification documentation.

CI additionally runs `scripts/verify-coordinator.ts` with synthetic GitHub responses and the real restricted Docker scanner over private downloaded-file equivalents. That verifies the standard-input transfer, native scan and source binding. It does not establish live App authentication or webhook delivery.

[Live App acceptance](github-app-verification.json) additionally exercised actual signed GitHub synchronization events through the durable queue, the real scanner container and App-owned checks. Native annotation readback preserved rule, path, line and severity; the safe revision had no annotations. Redelivery was not queued again, and a superseded revision failed before publication. These jobs used the single-job work command. The temporary webhook was disabled after acceptance, and the analysis-only PR was closed without merge. To run again, start the receiver and worker with private configuration, update the App to a new reachable HTTPS URL, preserve its signing secret and activate the webhook. Keep the App restricted to intended repositories.
